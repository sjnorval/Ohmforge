# Ohmforge project rules (Grok Build)

Grok Build also reads the root `AGENTS.md`; that file is the full guide and wins on any conflict. Short version:

1. Source of truth: `docs/DESIGN_AND_PLAN.md` (never edit it unless Stefan asks). Current tasks: `docs/ROADMAP.md`. Schematic wire routing: `docs/design/wire-routing.md`.
2. Current phase: **P2 (ESP32-C3 MVP) is in progress**; P1 Analog core is complete. P2 so far: ELF and ESP flash image loading (`of-firmware`), the C3 memory map, GPIO/IO MUX, UART0 TX, SYSTIMER with alarms, the interrupt matrix, TIMG0/1 and the watchdogs, and `Esp32c3Engine` (`of-soc-esp32c3`, `AGENTS.md` section 3c), with the blinky firmware in `firmware/` driving an LED end to end and a timer-interrupt firmware; the SPI flash, cache MMU, real-ROM boot (`power_on_rom`, esp-rom-elfs), ROM-lite flash boot (`boot_flash`), partition tables and the XIP blinky (`firmware/esp32c3-xip-blinky`) are on `main`; an unmodified esp-hal blinky (`firmware/esp32c3-esp-hal-blinky`) boots through the real ROM and espflash's ESP-IDF bootloader (fetched with the ROM, never committed; `tests/esp_hal_blinky.rs`) on `main`, with the CPU clock (`system`), RNG, PMP and trigger CSRs and RTC calibration; GPIO inputs are on `main` (#22) (V_IH/V_IL watches into `input_code` events, `FUN_IE`, 45 kΩ pulls in `PinOut::thevenin`, pin interrupts on matrix sources 16/17, exact-time input reads via `Bus::defer_load` and lazy `wfi`; AGENTS.md section 3c), the `switch` analog kind with `generic.pushbutton`, and `firmware/esp32c3-esp-hal-button` (polling and interrupt apps, `tests/esp_hal_button.rs`); the SAR ADC one-shot mode (`saradc`: conversions sample the circuit at their start via `Esp32c3Engine::link_adc` and `AnalogEngine::sample_on`, codes from the eFuse calibration) and LEDC PWM (`ledc`: exact-time PWM edges through GPIO matrix signals 45 to 50, no averaging), the `potentiometer` analog kind with `bourns.ptv09a-b103`, and `firmware/esp32c3-esp-hal-adc-pwm` (pot dimmer and LED fade, `tests/esp_hal_adc_pwm.rs`) are on `main` (#24), as is UART0 RX FIFO with serial Send delivery (#25); the common-components checklist is `docs/COMPONENTS.md`; the desktop app (`of-app --features gui`) plays the EILIi load screen (packed frames, skip / `--no-splash` / `OF_NO_SPLASH`) and is a live demo picker in `of-ui` (LED blink, pot dimmer with a run-time slider via `BuiltBoard::pot_params`, LED fade and push-button; schematic with an averaged on-screen LED, a window-tied current-scope ring with time/div zoom (playback down to 1e-6×), clickable SW1, configurable bench PSU, virtual V/A meters, serial monitor panel over `of-instruments::SerialMonitor` for UART0; #26 and #27). The analog solver holds a settled DC network and the hart caches decoded instructions (branch `p2-perf`). The dimmer and fade boot the fetched ROM and espflash bootloader (never bundled; `scripts/fetch-esp-rom-elfs.*`); they do not start from the app image alone, unlike the bare-metal blinky; the C3 hart has no `mie`/`mip` (`HartConfig::mie_mip`); next steps are in the roadmap's "First milestone" list. P1 covers `crates/of-analog`, `of-netlist::spice`, `ohmforge run`, the parts bridge `of_components::analog`, `AnalogEngine` under the `of-core` kernel and the AMS1117 macromodel (design notes in `AGENTS.md` section 3b). Phase one, the RISC-V core (`crates/of-cpu-riscv`, section 3a), is done. New analog features need an analytic test and an ngspice golden circuit (`* ngspice-replace:` for Ohmforge-only syntax), all within 1 %; new analog parts also need datasheet checks through the bridge. Register CPU engines before the analog engine.
3. Rust edition 2024, MSRV 1.95. On Windows, load the Build Tools `vcvars64.bat` environment for that machine first (`AGENTS.md` section 9). Then run `cargo fmt --all --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace`, the GUI check and the wasm32 check from `AGENTS.md`.
4. Licence: code is AGPL-3.0-or-later, parts data and docs CC-BY-SA-4.0. Dependencies must be AGPL-compatible (the permissive `deny.toml` allow list; no GPL-2.0-only or LGPL); never copy code from QEMU, CircuitJS, SimulIDE or Wokwi. riscv-tests (BSD-3) are built from source, never committed. Espressif's ROM ELFs (esp-rom-elfs: Apache-2.0 files, closed-source ROM code) are fetched by `scripts/fetch-esp-rom-elfs.sh`/`.ps1` (pinned release and SHA-256, cached in `.cache/`), never committed; ROM tests skip without them. ngspice is only ever run as an external tool to make golden CSVs (`scripts/gen-ngspice-golden.sh`); never link, vendor or ship it.
5. Git: report changes to Stefan and propose a commit breakdown; **commit only after his approval**. Commits are signed off (`git commit -s`) Conventional Commits. Remote `origin` is https://github.com/sjnorval/Ohmforge; `main` holds everything merged so far (PRs #7 to #12). New work goes on feature branches off `main` and reaches it only through pull requests Stefan merges; never push to `main`. Push only when Stefan says so, never force-push, never handle tokens. Every user-visible change adds a line under `## [Unreleased]` in `CHANGELOG.md`; pull requests follow the checklist in `.github/pull_request_template.md` (sign-off, tests, fmt/clippy/test, cargo-deny, AGPL-compatible deps, no ngspice linking, firmware ELFs rebuilt, docs, `AGENTS.md`, these rules and the roadmap updated) and get type, `phase:*` and `area:*` labels (`CONTRIBUTING.md`). Stacked PRs must be merged bottom-up: retarget each later PR to `main` (`gh pr edit --base main`), confirm it targets `main` before merging, and after each merge verify the tip is on `main`; never merge a later PR into its feature-branch base.
6. **Ohmforge** is the final name; crates use the `of-` prefix.
7. Simulation crates stay deterministic (virtual `SimTime`, no wall-clock) and wasm32-compatible.
