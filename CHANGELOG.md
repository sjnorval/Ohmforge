# Changelog

All notable changes to Ohmforge are recorded here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project will use [Semantic Versioning](https://semver.org/) from its first release (0.1, the end of P2; see [`docs/ROADMAP.md`](docs/ROADMAP.md)).

Add a line under **Unreleased** in every pull request with a user-visible change, in the matching section (Added, Changed, Deprecated, Removed, Fixed, Security). GitHub's generated release notes (`.github/release.yml`) list the pull requests; this file is the curated summary.

## [Unreleased]

Nothing has been released yet. Everything below is on `main` and will ship in 0.1.

### Added

- **Schematic router on the pot and button demos:** the dimmer, fade and push-button boards use the same orthogonal grid router as blink. Symbols, colours, stroke widths and labels are unchanged; only net paths that would have violated the routing invariants (body clearance, foreign-net colinear overlap) were allowed to move. Perpendicular crossings of a rail, which the hand-authored dimmer and button drawings already used, are now allowed at a high cost; hop glyphs remain a later PR.
- **Startup animation and still** (`assets/startup/`): the final 6 s, 736×400 social-preview-style animation ([`EILIi.mp4`](assets/startup/EILIi.mp4), concept EILIi) and its last-frame still ([`startup-still.png`](assets/startup/startup-still.png)). Planned as the app's load screen, played as converted frames (no video decoder in the app). Other concept videos stay on the pull request. Assets are CC-BY-SA-4.0.
- **Schematic wire routing design:** the P2 schematic editor's net routing (orthogonal grid, T-junctions, later waypoints) is specified in [`docs/design/wire-routing.md`](docs/design/wire-routing.md). No code change in this PR.
- **Scope time/div and slower playback:** the live LED-current scope has a 1-2-5 time/div control (10 µs/div to 1 s/div, five divisions) with mouse-wheel zoom and a Hold freeze. Playback speed goes down to 1e-6× on a logarithmic slider. Wide windows decimate so the ring stays within 32 768 samples; when zoomed in the scope records as finely as 1 µs (the analog solver's `max_step` is 5 µs; PWM and GPIO edges still occur at their exact simulated time). Samples are only dropped once they have left the visible plot (plus a small margin); a sample grid stops very slow playback from packing the ring and clearing the trace too early.
- **UART0 baud-timed RX and serial-monitor hex/find:** host bytes queued into UART0 arrive one frame at a time at the configured baud (start + data + parity + stop). RX interrupts follow the C3 TRM: `RXFIFO_FULL` (count > `CONF1.RXFIFO_FULL_THRHD`), `RXFIFO_TOUT` (`CONF1.RX_TOUT_EN` and `MEM_CONF.RX_TOUT_THRHD` bit times of idle with data in the FIFO), and `RXFIFO_OVF`, with `INT_RAW` / `INT_ST` / `INT_ENA` / `INT_CLR`. The SoC UART TX log is capped at 64 KiB, like the serial monitor. The serial panel can show a hex dump and find text or hex bytes.
- **Electrically honest bench I/O:** GPIO V_IH / V_IL watches track the live `vdd` rail (0.75 / 0.25 of the present node voltage) so a Vset change takes effect without Reset. The on-schematic SW1 uses the same deterministic contact-bounce train as `tests/esp_hal_button.rs` (seed 0 is exact; other seeds jitter the intervals). Bounce is on by default and can be turned off or re-seeded from the demo sidebar; the schematic drawing is unchanged.
- **Faster live playback and a bounded scope:** the analog solver holds a settled DC solution instead of re-solving on every kernel slice or GPIO poll (no-op supply and pin `set`s are not discontinuities). The RISC-V hart caches decoded instructions, invalidated by `fence.i` and stores. The live LED-current scope is a fixed-capacity ring whose retention follows the visible time window (plus a small margin, at least 20 ms). PWM edges still reach the circuit exactly; results stay deterministic. On a release build, button-irq is far above realtime when the core is in `wfi`; blink / dimmer / fade stay around 0.15–0.18× and button-poll around 0.11×, limited by the instruction interpreter.
- **Live desktop simulation:** the bundled demos run continuously on a worker thread (not the UI thread) at a user-set speed (default 1× realtime, 1e-6×–10×) with a visible realtime factor. The pot slider and on-screen push button take effect immediately, without Reset. Live readouts show pot wiper voltage, the last UART ADC/duty line, PWM duty and frequency, LED current, and the bench supply's output voltage and current. The LED current scope keeps scrolling. New picker entries: push button (poll) and push button (irq), with a clickable SW1. Schematic tooltips show part values on hover; colours, layout and drawing style are unchanged.
- **Virtual voltmeter and ammeter:** pick a meter type and click point A then point B on the live schematic. A voltmeter reads V(A) − V(B) between any two nodes. An ammeter reads the current through the single user-visible part or wire joining A and B, without inserting a sense element; if those points are on the same net or no unique branch joins them, the UI says so and the meter is not placed. Several meters can be on the schematic at once, each live and removable, drawn in the existing teal stroke language.
- **Configurable bench supply:** a PSU on the virtual schematic feeds the simulated `vdd` rail (pot top and ESP32-C3 VDD as modelled). The user can set voltage, series resistance, a CC/CV current limit, and on/off. GPIO high-side drivers source from that rail so LED current counts toward the limit. Outside the ESP32-C3 recommended 3.0–3.6 V range the UI warns that brownout/undervoltage is not modelled.
- **Desktop demo picker:** the app (`of-app --features gui`) can switch between the LED blink, pot dimmer and LED fade. A slider turns `RV1` at run time (`BuiltBoard::pot_params`); the on-screen LED and current trace use a short-window average of LED current (display only; the circuit still sees every exact PWM edge). The dimmer and fade boot the committed esp-hal images through the fetched ESP32-C3 ROM and espflash bootloader; if those files are missing, the UI explains how to run `scripts/fetch-esp-rom-elfs.ps1` or `.sh`. App-only and ROM-lite boots were tried and do not start these esp-hal apps. The serial monitor Send path is unchanged.
- **UART0 RX FIFO:** host bytes can be pushed into an instant 128-byte RX FIFO (`Esp32c3::push_uart_rx`); `STATUS.RXFIFO_CNT` and FIFO reads work. The blink serial monitor Send path delivers when attached (`Delivery::Attached`). Baud timing and RX interrupts still to do.
- **ESP32-C3 ADC and LEDC PWM**: the SAR ADC's one-shot conversions (ADC1 channels 0 to 4 and ADC2 channel 0, all four attenuations, 12-bit, 25 SAR clocks per conversion, done interrupts) sample the circuit's node voltage at the instant a conversion starts, and give the code that esp-hal's and ESP-IDF's curve-fitting calibration turns back into the input voltage (within 3 mV) using the chip's eFuse calibration. The LED PWM controller (four timers with fractional dividers, 1- to 14-bit resolution, six channels with Hpoint, duty dither, hardware fades, overflow counters and interrupts) drives pins through the GPIO matrix, and every PWM edge reaches the circuit at its exact counter tick. New `potentiometer` analog kind and a 10 kΩ linear 9 mm potentiometer part (`bourns.ptv09a-b103`) that can be turned at run time, and esp-hal firmware (`firmware/esp32c3-esp-hal-adc-pwm`: a pot dimmer and a hardware LED fade) tested end to end through the real ROM.
- **ESP32-C3 GPIO inputs**: circuit nodes now drive pins. `GPIO_IN` follows the node voltage through V_IH/V_IL threshold watches (0.75/0.25 VDD, with hysteresis), gated by the IO MUX input enable; the weak pull-up and pull-down (45 kΩ) are part of the analog pin model; pin interrupts (rising, falling, any edge, low and high level; enable, status and clear registers) reach the CPU through the interrupt matrix; the GPIO input-select matrix routes pins to peripheral inputs; pads start as the datasheet's reset table says. Input reads are exact in time: the CPU stops before reading an input until the circuit has caught up, and a core sleeping in `wfi` wakes at the input event itself. New `switch` analog kind and a 6 mm tactile push-button part (`generic.pushbutton`), and esp-hal button firmware (`firmware/esp32c3-esp-hal-button`: polled and interrupt-driven, no debouncing) tested with contact bounce, the internal pull-up and an RC edge.
- **Common components checklist** (`docs/COMPONENTS.md`): the parts the library should cover, with model type, interface, priority and what each still needs from the simulator.
- **esp-hal blinky through the full boot path**: an unmodified esp-hal 1.2.2 blinky (`firmware/esp32c3-esp-hal-blinky`, built with espflash 4.7.0, reproducible) boots on the ESP32-C3 model through the real ROM and espflash's ESP-IDF second-stage bootloader (fetched with the ROM, never committed) and drives the LED circuit. New models: the CPU clock (SYSTEM), the RNG, PMP and debug trigger CSRs, TIMG RTC calibration, UART0 configuration registers and GPIO pin and input select registers.
- **ESP32-C3 ROM boot, flash and cache MMU:** a 4 MiB SPI flash chip behind the SPI0/SPI1 memory controllers and the cache MMU (64 KiB pages into the IROM and DROM windows); Espressif's real mask ROM runs on the model (`Esp32c3::power_on_rom`): it prints its banner and reset cause, direct boots flash, loads and SHA-256-checks an image at flash offset 0, reboots after watchdog resets and honours download-mode strapping. The ROM ELF comes from esp-rom-elfs and is never committed: `scripts/fetch-esp-rom-elfs.sh`/`.ps1` fetch a pinned, checksummed release, and the ROM tests skip without it. A ROM-lite fast boot (`Esp32c3::boot_flash`) boots direct-boot flash, the app from the partition table at 0x8000, or the image at 0, without running the ROM. Also new: partition table parsing and writing (with the MD5 row), 64 KiB-aligned flash image layout (`EspImage::align_flash_segments`), the SHA accelerator, eFuse (blank chip), the USB Serial/JTAG console, the C3 performance-counter CSRs, and an XIP test firmware (`firmware/esp32c3-xip-blinky`) that runs in place from flash.
- **Community and contributor setup:** issue forms (bug report, feature request, new part or model), a pull request checklist, `SECURITY.md` with private vulnerability reporting, `SUPPORT.md`, Dependabot for Cargo and GitHub Actions, this changelog and release-note categories.
- **Serial monitor (lean console):** reusable `of-instruments` model and `of-ui` panel (timestamps, clear/copy, baud, Send). Host→device bytes queue until a consumer attaches UART RX; the blink demo attaches and delivers into the SoC RX FIFO.
- **Desktop blink demo** (#11): `cargo run -p of-app --features gui` shows a live ESP32-C3 blink schematic, GPIO8 through a 330 Ω resistor to a red LED, with the LED lit from the simulated current, an LED current trace and the firmware's UART0 output. The desktop app now uses eframe's wgpu backend.
- **ESP32-C3 interrupts, timers and watchdogs** (#10): the interrupt matrix and CPU interrupt controller (62 sources, 31 lines, priority, threshold, edge and level), traps into vectored `mtvec`, SYSTIMER alarms in target and period mode, timer groups TIMG0/1, and the MWDT, RTC and super watchdogs, whose resets reboot the loaded image. New timer-interrupt test firmware in `firmware/esp32c3-timer-irq`.
- **ESP flash images** (#10): a parser and writer for the ESP image format (header, segments, checksum, optional SHA-256, with our own SHA-256), and boot from a parsed image with a chip ID check.
- **ESP32-C3 blinky end to end** (#8): an ELF32 RISC-V reader (`of-firmware`) and direct ELF boot; the C3 memory map, GPIO and IO MUX output with a Thevenin pin model, UART0 TX capture and SYSTIMER; `Esp32c3Engine` under the `of-core` kernel; and a zig-built blinky firmware that drives a parts-library LED and resistor in the analog solver, with CI checking the firmware rebuilds byte for byte.
- **RISC-V CPU core** (#7): an RV32IMC (+A optional) interpreter with Zicsr, machine-mode traps and interrupts, a cycle model and a debugger API, passing 75 of 77 riscv-tests (2 expected-unsupported).
- **Analog core** (#7): a sparse MNA solver (faer sparse LU) with DC operating point, nested DC sweeps, AC and transient analyses; R, C, L, K, independent and controlled sources (including POLY), switches, diodes and LEDs, Gummel-Poon BJTs and level 1 and 3 MOSFETs, with temperature effects; a SPICE netlist subset parser; `ohmforge run netlist.cir` with CSV and VCD output; an AMS1117-3.3 macromodel; the parts-to-solver bridge; and the analog engine under the `of-core` kernel. 39 reference circuits match ngspice within 1 %.
- **Foundations:** the Cargo workspace, the `of-core` deterministic kernel (`Engine` trait, quantum slices, breakpoints), the `part.toml` loader and example parts, CI on Linux, Windows and macOS with fmt, clippy, cargo-deny, wasm32 and GUI checks, the README banner, favicon and app icon, and UX research specs (#1, #3, #5).
- **Schematic wiring model:** the blink demo declares components, pins, nets and hand-authored fixture routes in `of-ui` (`crates/of-ui/src/wiring`). The painted schematic is unchanged.
- **Schematic wire router:** an orthogonal grid router in `of-ui` generates the blink demo net paths. Symbol strokes (including the R1 zigzag) stay hand-drawn; PSU pins leave the body perpendicularly. Stroke widths and colours are unchanged.

### Changed

- **ESP32-C3 eFuse:** the chip now carries ADC calibration (block version 1 and the ADC1 init codes and calibration voltages of Espressif's documented example chip) instead of a blank calibration block.
- **ESP32-C3 GPIO:** a pin whose `GPIO_FUNCn_OUT_SEL` selects a modelled peripheral signal (the LEDC channels) follows that signal, with the matrix's output inversion and output-enable selection.
- **ESP32-C3 pins:** `PinOut` gains `pull_up` and `pull_down`, and `pin_code` carries them, so `all_pin_codes` yields 48 codes per pin instead of 12; the IO MUX reset values now follow the datasheet (input enable and pull-ups on the listed pins, drive strength 1 on GPIO2 to GPIO5 and 3 on GPIO18 and GPIO19).
- The ESP32-C3 core performs misaligned loads and stores in hardware, as the chip does, and its performance counter counts from reset; the hart follows the CPU clock the firmware selects instead of always running at 160 MHz.
- ESP32-C3 flash windows are read through the cache MMU, which IROM and DROM share; the test firmware's read-only data moved to 0x3c01_0020 so it does not share flash with code.
- The CPU core's `mie`/`mip` CSRs are optional (`HartConfig::mie_mip`); they are off for the ESP32-C3, which has neither (#10).
- Every change to `main` needs the maintainer's review through `CODEOWNERS` and the main-branch ruleset (#9).
- The README has a roadmap summary, and the roadmap has a parked "Future ideas" section (#12).
- Relicensed: code is AGPL-3.0-or-later and parts data, artwork and docs are CC-BY-SA-4.0 (previously MIT OR Apache-2.0 and CC-BY-4.0) (#6).
