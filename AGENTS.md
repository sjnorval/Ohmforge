## 1. What this project is

**Ohmforge** is an open-source, true-to-life **ESP32 circuit simulator in Rust**. It runs unmodified ESP32 firmware (ESP-IDF, Arduino-ESP32, esp-hal, MicroPython ELF files) against a SPICE-grade analog circuit in one deterministic simulation. Every placed part is a real, orderable part, so the bill of materials (MPN, supplier, ZAR cost) and a real-world build checklist come straight from the design. It targets a native desktop app and a WASM web app from one codebase.

If your change contradicts it, stop and propose an update to the plan (or an RFC in `rfcs/`) instead of silently diverging. Do not edit `docs/DESIGN_AND_PLAN.md` unless the owner asks.

The engine owns nets, solvers, time, events and measurement; every real part, the ESP32-C3 and the bench PSU are components on one API. New parts follow the engine API (no per-demo glue in `of-ui`, no hidden connections to ground); demos become circuit files in E4.

## 2. Architecture in one minute

- One scheduler (`of-core`) owns virtual time as a `u64` picosecond clock; every engine advances under it, so runs are reproducible.
- CPU cores execute firmware in instruction quanta and stop early on any I/O register access; the analog solver advances to that exact instant first.
- Nets with only digital endpoints are solved by the event-driven logic kernel (`of-digital`); any net touching an analog part is promoted to the MNA solver (`of-analog`).
- ESP32-C3 (RISC-V) runs on our own core first. Classic ESP32/S3 (Xtensa) uses Espressif's QEMU as a **separate GPL process** through `of-cpu-qemu-ipc` until our own Xtensa core exists.
- Parts are data (`parts/**/part.toml`, parsed by `of-parts`) plus behaviour (Rust in `of-components`, or sandboxed WASM via `of-plugin-wasm`) implementing the `Component` trait in `of-component-api`. The base engine (`of-engine`) elaborates components into the solvers ([`docs/design/engine-components.md`](docs/design/engine-components.md), RFC 0001); today the demos still assemble their circuits in `of-ui` until E3/E4.

## 3a. `of-cpu-riscv` design notes

- **Modules:** `bus` (the `Bus` trait plus a `Ram` test device), `decode` (32-bit decoder, `Instr`, disassembler via `Display`), `compressed` (RVC to 32-bit expander), `csr` (machine CSR file with WARL masking), `trap` (exception codes, `mcause`, interrupt selection), `timing` (`TimingModel` cycle costs), `hart` (`Hart`, `HartConfig`, execution), `asm` (instruction encoders for tests and tools).
- **ISA:** RV32I + M + C + Zicsr + Zifencei; A is optional (`Extensions { a }`: off for the C3, on for the C6 and the riscv-tests run). Machine mode only; `mstatus.MPP` is hard-wired to M. No U-mode, PMP or debug triggers yet. A 4096-line direct-mapped decode cache (invalidated by `fence.i`) skips the bus fetch on hits; `Hart::run` / `run_until` are generic over the concrete `Bus` so the SoC path is monomorphised.
- **Bus contract:** `read`/`write` with `Size` and `AccessKind`; `wait_states` adds cycles; `csr_read`/`csr_write` let the SoC add custom CSRs (unknown CSRs fall through to the bus, otherwise illegal instruction; `csr_cycles` hands the bus the hart's elapsed cycles first, for counter CSRs); `take_sync_request` lets a peripheral access end the current quantum so the analog solver can catch up; `defer_load(addr, now)` lets the SoC stop the hart *before* a load whose value depends on engines that are behind (`RunExit::Deferred(pc)`, `StepOutcome::Deferred`: nothing executes and no time passes; run again once they catch up).
- **Time:** `Hart::local_time()` = time origin + elapsed cycles x clock period (6250 ps at 160 MHz). `run_until(bus, SimTime)` runs a quantum; `idle_until` lets time pass in `wfi`. `elapsed_cycles` is monotonic; `mcycle`/`minstret` are the software-visible counters (writable, `mcountinhibit` honoured).
- **Debugger/GDB:** `step` returns `StepOutcome` (retired/trapped/waiting/halted); `run` returns `RunExit` (budget, breakpoint, halted, WFI, sync, deferred). Breakpoints are a `BTreeSet<u32>`, skipped on the first instruction of a run so resume works. `EbreakAction::Halt` turns `ebreak` into a debugger stop. `disassemble_at`, `reg`/`set_reg`, `pc`/`set_pc`, `csr_peek`/`csr_poke`, `halt`/`resume`/`reset`.
- **Interrupts:** the SoC drives lines with `set_interrupt_line`/`set_interrupt_lines` (`mip` is read-only to software). C3 mask is lines 1 to 31; order is MEI, MSI, MTI, then lowest line (the C3 interrupt matrix applies priority/threshold before the core and presents only the winning line). `HartConfig::mie_mip` is false for the C3: like the real chip it has no `mie`/`mip` CSRs (accessing them is an illegal instruction) and a pending line is taken whenever `mstatus.MIE` is set; `generic_imac` keeps both CSRs for the riscv-tests. Direct and vectored `mtvec`.
- **Timing numbers** in `TimingModel::ESP32C3_ESTIMATE` are estimates until calibrated on hardware; do not present them as measured.
- **Compliance:** `tests/riscv_tests.rs` runs riscv-tests ELFs (BSD-3-Clause) from `target/riscv-tests` (or `OF_RISCV_TESTS_DIR`) and skips if absent. Build them with `scripts/build-riscv-tests.sh` or `.ps1` (pinned commit, zig/gcc/clang). Never commit the binaries. `rv32mi-p-breakpoint` (triggers) and `rv32mi-p-pmpaddr` (PMP) are listed as expected-unsupported.

## 3b. `of-analog` design notes

- **Modules:** `matrix` (sparse MNA system on faer sparse LU, plus the complex AC solve), `circuit` (`Circuit`, `Device` trait, `Setup`, `LoadCtx`), `devices` (`passive` incl. `MutualInductance`, `sources`, `switch`, `diode` incl. LED, `bjt`, `mosfet`, `limit` incl. temperature helpers), `integrate` (`Method`, `States`, `Integrator`), `waveform` (PULSE/SIN/EXP/PWL), `analysis` (`dc` incl. `dc_sweep_nested`, `ac`, `newton`, `tran`), `results` (`OpPoint`, `Waveforms`, `AcResult`, CSV/VCD), `netlist` (`build(&Deck)`, `add_deck` to add a deck to an existing circuit), `engine` (`AnalogEngine`).
- **Unknowns:** variable 0 is ground; node voltages first, then internal nodes (`v(dev#suffix)`, for RS/RB/RD, ESR/ESL, `rser` etc.) and branch currents `i(name)` for V sources, inductors, E and H (internal branches such as `i(c1#esl)` are hidden). Output omits internal nodes. Current signs follow SPICE: `i(v1)` flows into the + terminal.
- **Device contract:** `setup` claims matrix slots (`Setup::slot`/`slots2`), branches, internal nodes and state slots once; `load` stamps the Newton companion model every iteration (matrix entries plus RHS `i - g*v`). Charges are integrated via `LoadCtx::integrate(k, cap)`, which marks state `k` for the truncation-error estimate. Devices report limiting (`cx.limited`) so the iteration is not counted as converged, and `next_breakpoint` for source corners. Optional hooks: `ac_stimulus` (AC sources) and `probes` (derived outputs such as an LED's `popt(d1)` in W and `bright(d1)` = I/IF, appended to OP and sweep results). Setup priority: 0 for branch owners, 1 default, 2 for `K` (needs both inductor branches).
- **Matrix:** pattern fixed at `finalize`; symbolic LU computed once; numeric refactorisation skipped when values are unchanged (linear circuits after the first step). No rayon: single-threaded and deterministic, wasm32-friendly. A non-finite solution is reported as a singular matrix naming the suspect unknown.
- **DC:** Newton (`itl1`) with SPICE3 pnjlim/fetlim/limvds, then damped Newton, gmin stepping (diagonal shunt from `gmin*10^10` down by decades, with back-off) and source stepping (both use `itl2`, as in SPICE). The transient operating point uses waveform values at t = 0; `.op` uses the DC value. Nested `.dc` restarts the inner sweep for each outer value and adds a column named after the outer source.
- **AC:** after the DC operating point and a `TranInit` load, every device is loaded in `Mode::Tran` with `small_signal = true` (no limiting, no state advance) using `Integrator::small_signal(ag0)`: `ag0 = 0` gives G and `ag0 = 1` gives G + C, so C is the difference on the same CSC pattern. Each frequency solves `(G + jωC) x = b` with the cached symbolic LU. Devices need no AC-specific code, but must stamp operating-point capacitances when `small_signal` is set (MOSFET Meyer uses 2x the half-cap, as SPICE's INITSMSIG). BJT excess phase is transient-only.
- **Transient:** first step and the step after every breakpoint are backward Euler, then trapezoidal or Gear-2 (`.options method=gear`). Step control is the SPICE3 `CKTterr` charge-based estimate (divided differences of every integrated charge, `trtol` 7, `chgtol` 1e-14); reject below 0.9 h, grow at most 2x; Newton failure divides h by 8. Max step `min(tstep, span/50)` unless `tmax` is given. Breakpoints land exactly; after one, h = 0.1 x min(h, gap to the next). `Integrator::h_prev` is the previous step (BJT excess phase). Switches have no timestep control yet: give switching circuits a `tmax`. The step loop is `analysis::tran::Stepper`, shared by `transient()` and the engine.
- **Models** follow the published SPICE3/ngspice equations: diode (Shockley, breakdown knee with NBV/TCV, depletion/diffusion charge); Gummel-Poon BJT (`qb` with Early and high injection, XTF/VTF/ITF, IRB/RBM, XCJC, CJS to the substrate node, PTF excess phase); MOS1 Shichman-Hodges and MOS3 (ngspice's corrected form, i.e. not `badmos3`) with mode swap, bulk diodes and depletion caps, Meyer caps from TOX; SW/CSW switches with hysteresis; `K` as `M = k·sqrt(L1·L2)`. Temperature: devices take `with_temp(K)`; the builder uses `.temp`/`.options temp` (°C, default 27), `.options tnom`, model `tnom` and instance `temp`/`dtemp`; passives scale by `1 + tc1·dT + tc2·dT²`. Missing MOS KP/PHI/GAMMA/VTO are derived from TOX/UO/NSUB/NSS/TPG as in SPICE. Unsupported model parameters produce a build warning, never silent wrong results; MOSFET `LEVEL` other than 1 or 3 is an error.
- **Engine (`AnalogEngine`, kernel side in `of_core::engine`):** the kernel cuts time into slices ending at the earliest of now + quantum, the next event, breakpoint, the run end and every engine's `next_event`; engines advance in registration order and an early stop shrinks the slice for the later ones, so **register CPUs first and the analog engine last** (a CPU may run up to one quantum ahead; MMIO accesses end its quantum). The analog engine keeps integration history across slices (no restart at slice ends); events map codes to `SetParam` changes (`on_code`) and force a backward-Euler restart (`discontinuity`); `watch(signal, level, edge, target, code)` refines the step down to the crossing within `EngineConfig::resolution` (100 ps default) and posts an event at that time. GPIO outputs are `PinDriver`s (Norton source, `v`/`r` parameters, Hi-Z = 1 TΩ). `value(name)` reads any unknown or probe; `record` keeps `Waveforms`.
- **POLY sources:** `E`/`G` with `POLY(n)` (n ≤ 8) use the SPICE2 term order (constant, linear, then products by degree in lexicographic index order) with the exact Jacobian. ngspice accepts them natively, but its XSPICE code drops `trtol` to 1 when they are present, so golden decks using them set `.options trtol=1`.
- **Parts bridge (`of_components::analog`):** a `part.toml` gives `[[pin]]` (number, name) and `[analog]` (`kind` = resistor, capacitor, led, diode, npn, pnp, load, switch, potentiometer or subckt; `pins` in device order; `params` as plain values or `{ value/typical, min, max, tolerance }`; `file`/`subckt` for subcircuit parts). `Placement::new(refdes, part, &[(pin, net)])` with `.with(param, value)` overrides; a `Board` has placements, a `Corner` (Typical, Min, Max, Deviation(k)) and `Env` (temp/tnom). Overrides keep the part's relative spread at a corner. Primitive parts become devices named by lower-case refdes; subcircuit parts are flattened per instance as `x<refdes>` (so `v(xu1.tj)`); net `0`/`gnd` is ground; every pin must be connected. A `switch` (`generic.pushbutton`) is a resistor of `ron` or `roff` (placement `closed = 1.0` closes it); `BuiltBoard::switch_param(refdes, closed)` is the `SetParam` that presses or releases it at run time (map it to an event code with `AnalogEngine::on_code`); contact bounce is a sequence of such events (`of_components::bounce`: seeded, toggleable, default train matches `tests/esp_hal_button.rs`). A `potentiometer` (`bourns.ptv09a-b103`; pins end, wiper, end) is two resistors `<refdes>_a` (first pin to wiper, `position · resistance`) and `<refdes>_b` (the rest), each at least 1 mΩ (`POT_MIN_LEG`); placement `position` 0 to 1 (default 0.5); `BuiltBoard::pot_params(refdes, position)` gives the two `SetParam`s that turn it. `to_spice` writes the same board as a SPICE deck. Ground truth for new analog parts: a datasheet test through the bridge plus an ngspice golden circuit.
- **AMS1117 macromodel** (`parts/regulators/ams1117/ams1117.lib`, our own, CC-BY-SA-4.0): standard primitives only (depletion-NMOS quiescent current, ideal reference with supply coupling, Gm error amplifier with clamps, PNP driver into an NPN pass device, sense resistor and current limiter, POLY power into an `Rth`/`Cth` thermal node with a thermal limit near `tsd`). `v(x.tj)` is the rise over `tamb`. Matches the datasheet (Vout, line/load regulation, Iq ≈ 5 mA, dropout ≈ 1.1 V at 0.8 A, limit ≈ 1.1 A, ripple rejection ≈ 72 dB at 120 Hz) and ngspice (`ams1117_*` circuits). Not modelled: the ADJ variant, behaviour below about 1.5 V in, and electro-thermal coupling into other devices.
- **Validation:** `tests/analytic.rs` (closed-form answers) and `tests/ngspice_compare.rs` (circuits in `tests/circuits`, golden CSVs in `tests/golden`, regenerated with `scripts/gen-ngspice-golden.sh [name ...]`). ngspice is run only as an external program to produce data: never link, vendor, port or ship it (its tree contains a GPL file). Ohmforge-only syntax (ESR/ESL, `rser`, `led` models) is rewritten for the reference run with `* ngspice-replace: FROM => TO` lines. Limits: 1 % of the reference signal's span (tran/DC); AC magnitude 1 % per point (floor 1e-3 of the peak) and phase 1 % of 180°; nested DC row by row. Fast-edge circuits set `tmax` so both simulators resolve the edges. `.include` paths are relative to the circuit file (the golden script rewrites them for ngspice). `of-components/tests` holds the bridge tests, AMS1117 datasheet checks, the MVP board built from parts (compared with the `mvp_board` golden) and a scripted-CPU co-simulation.

## 3c. `of-soc-esp32c3` design notes

- **Modules:** `map` (address map constants from the TRM), `bus` (`SocBus`: memories plus peripheral dispatch, implements `of_cpu_riscv::Bus`), `gpio` (GPIO, GPIO matrix output select and input select (`Gpio::peripheral_input`), `GPIO_IN`, pin interrupts (`INT_TYPE`, `INT_ENA`, `STATUS` with W1TS/W1TC, `PCPU_INT`/`PCPU_NMI_INT`), `GPIO_PINn` with open drain, IO MUX `MCU_SEL`/`FUN_DRV`/`FUN_IE`/`FUN_WPU`/`FUN_WPD` with the datasheet's reset pad settings, `PinOut`), `uart` (UART0: TX capture, instant RX FIFO via `push_rx`/`Esp32c3::push_uart_rx`, `STATUS.RXFIFO_CNT`, configuration registers, `Uart::baud`), `systimer` (two 16 MHz units, three comparators, interrupts), `intmatrix` (`IntMatrix`: source map, CPU interrupt controller enable/type/priority/threshold/clear), `timg` (TIMG0/1: timer 0, MWDT and RTC slow-clock calibration), `rtc_cntl` (RTC WDT, super watchdog, RTC interrupt registers), `watchdog` (shared stage logic, `ResetKind`, `ResetSource`, `WatchdogReset`), `flash` (`SpiFlash`: 4 MiB NOR chip, JEDEC ID, read/program/erase commands), `spi_mem` (SPI0/SPI1 memory controllers: `CMD` operations and user transactions, run at once), `cache` (EXTMEM registers and the 128-entry MMU table), `csr` (C3 CSRs: the performance counter (one counter behind the machine and user names, `mpcmr` resets to count and saturate), user trap CSRs, PMP and debug trigger CSRs (stored, not enforced)), `efuse` (wafer v0.3, ADC calibration of Espressif's example chip), `saradc` (`SarAdc`: one-shot conversions, `code_for`, `calibrated_mv`), `ledc` (`Ledc`: timers, channels, fades, `SignalChange`), `sha` (SHA accelerator, SHA-224/256), `usb_serial` (USB Serial/JTAG console capture), `rom` (`RomImage` from an esp-rom-elfs ELF, pinned release constants), `bootloader` (pinned espflash bootloader constants, `espflash_flash_image`), `system` (SYSTEM `CPU_PER_CONF`/`SYSCLK_CONF`: CPU clock source and divider), `rng` (RNG data register, deterministic xorshift), `boot` (ROM-lite flash boot), `soc` (`Esp32c3`: hart + bus, `power_on_rom`, `boot_flash`, `write_flash`, `load_elf`, `load_flash_image`, `run_slice`/`run_until`, `resets`, time-stamped `PinEdge`s and `UartByte`s), `engine` (`Esp32c3Engine`, `PinLink`, `pin_code`, `input_code`, `input_watches`, `adc_request_code`, `adc_value_code`).
- **Memory map:** internal ROM (IBus 0x4000_0000, 384 KiB; ROM1 also at DBus 0x3ff0_0000), SRAM through IRAM 0x4037_c000 and DRAM 0x3fc7_c000 (same bytes; DRAM = IRAM - 0x70_0000), flash cache windows IROM 0x4200_0000 and DROM 0x3c00_0000 (8 MiB each, read through the MMU: entry `(addr & 0x7f_ffff) >> 16` gives the 64 KiB flash page, bit 8 marks it invalid; both windows share the one table, so IROM and DROM at the same window offset see the same flash page; an access with the cache off, the bus shut in `ICACHE_CTRL1` or an invalid entry is an access fault, where hardware raises the cache error interrupt; no cache lines or miss timing), RTC fast 0x5000_0000, peripherals 0x6000_0000 to 0x600d_0fff. Fetch only from IRAM, IROM and ROM; ROM and flash are read-only to the hart (loaders use `SocBus::load`; software writes flash through SPI1 commands). Also modelled for the ROM: `GPIO_STRAP` (default `0x0c`, SPI fast flash boot; `STRAP_DOWNLOAD` for download mode), `RTC_CNTL_RESET_STATE` (reset cause), SHA, USB Serial/JTAG console, eFuse with ADC calibration (block version 1, ADC1 init codes and calibration voltages of Espressif's documented example chip; `efuse::adc1_cal_code`).
- **Boot:** three ways. (1) **Real ROM:** `power_on_rom(&RomImage)` puts Espressif's ROM (revision 3, `esp32c3_rev3_rom.elf` from esp-rom-elfs; `RomImage::from_elf` places the allocated sections and rebuilds the `.data` initial values at the ROM's unpack-table sources) at 0x4000_0000 and resets into it. Verified paths: banner and reset cause, blank flash (`invalid header: 0xffffffff`), direct boot (magic `0xaedb041d` twice at flash 0: identity MMU map, jump to 0x4200_0008), loading and SHA-256-checking a RAM image at flash 0 (`load:`/`entry` lines), MWDT0 resets back into the ROM (`rst:0x7 (TG0WDT_SYS_RST)`), and download strapping (`waiting for download`). ESP-IDF second-stage bootloader: espflash's prebuilt bootloader (ESP-IDF v6.1) loads, reads the partition table at 0x8000, verifies the app and boots `firmware/esp32c3-esp-hal-blinky` through the cache MMU (`tests/esp_hal_blinky.rs`). Not run: UART RX download protocol. (2) **ROM-lite:** `boot_flash()` (module `boot`) stands in for the ROM and the second-stage bootloader in zero time: direct boot, else the app from the partition table at 0x8000 (`factory`, else lowest `ota_n`, else `test`; no OTA data), else the image at 0; flash-mapped segments must sit at a flash offset congruent to their address mod 64 KiB (`EspImage::align_flash_segments` writes such images). (3) **Direct load:** `load_elf` / `load_flash_image` copy RAM segments, write flash-window segments to flash at their window offset with an identity MMU map (so IROM and DROM content must not share window offsets: the test firmware puts `.rodata` at 0x3c01_0020), and set the PC. Watchdogs start disabled for (2) and (3); `arm_boot_watchdogs()` gives the state the ROM leaves on a flash boot (MWDT0 stage 0 system reset after about 325 ms, RWDT, super watchdog after 1 s); `power_on_rom` arms them itself under SPI-boot strapping. A watchdog reset (logged in `resets()`) resets the hart and peripherals, sets the reset cause and boots again the same way (ROM from the reset vector, ROM-lite, or the loaded image), re-arming boot watchdogs unless it was a CPU-only reset.
- **CPU clock:** the hart runs at the clock `SYSTEM` selects (`Esp32c3::cpu_hz`, applied on every sync; `HartCycles` time keeps its origin when the period changes): XTAL/2 = 20 MHz at power-on (the `SYSCLK_CONF` reset value; the ROM leaves it on the model, so ROM timing is unverified against hardware), 80 MHz from the PLL once the ESP-IDF bootloader sets it, 160 MHz in esp-hal with `CpuClock::max()`. ROM-lite and direct loads start at 160 MHz. APB-timed blocks (TIMG, watchdogs) always count at 80 MHz, also while the CPU runs from XTAL, where hardware's APB would follow it.
- **Timing simplifications (boot):** UART output has no baud timing (`Uart::baud` reports the configured rate); SPI flash operations, cache sync/preload/lock operations and SHA blocks complete at once; cache hits and misses cost nothing extra.
- **Peripherals:** every peripheral access sets a sync request; `Esp32c3::run_slice` then stamps pin changes and UART bytes with `hart.local_time()` (end of the instruction) and latches SYSTIMER. Writes to timed blocks (SYSTIMER, TIMG, RTC_CNTL) are applied at that same instant (`SocBus::settle`); interrupt-matrix writes apply at once. Slices also end at `SocBus::next_event()` (the next alarm or watchdog stage), so interrupts and resets happen at their exact time, and `wfi` idles to the next event. Interrupt sources are recomputed after every sync and the matrix hands the hart a single line. GPIO pin interrupts are interrupt matrix sources 16 (`GPIO`) and 17 (`GPIO_NMI`). Not modelled yet: the controller's few-cycle latency, SYSTIMER 52-bit wrap and stall-on-halt, the super watchdog's reset flag, the GPIO input synchronisers and glitch filter (no input delay), GPIO wake-up from sleep, and IO MUX direct (non-matrix) peripheral inputs. Unmodelled peripheral registers read back the last write and are counted in `SocBus::unmodelled()`: check it when new firmware misbehaves.
- **ROM tests:** `tests/rom_boot.rs`, `tests/esp_hal_blinky.rs`, `tests/esp_hal_button.rs` and `tests/esp_hal_adc_pwm.rs` need `esp32c3_rev3_rom.elf` from esp-rom-elfs (Apache-2.0 files; the ROM code is Espressif's and closed source); the esp-hal tests also need espflash's ESP32-C3 bootloader (`espflash-v4.7.0-esp32c3-bootloader.bin`, built from ESP-IDF, Apache-2.0). Fetch both with `scripts/fetch-esp-rom-elfs.sh` or `.ps1` (pinned release `20260528` and espflash `v4.7.0`, SHA-256 checked, into `.cache/esp-rom-elfs/<release>`, `$RUNNER_TEMP` in CI, or `OF_ESP_ROM_DIR`). The tests (`tests/common/mod.rs`) check each file's SHA-256 (`rom::C3_ROM_SHA256`, `bootloader::C3_BOOTLOADER_SHA256`) and skip when it is absent unless `OF_REQUIRE_ESP_ROM` is set (CI sets it). `bootloader::espflash_flash_image` sets the bootloader header to 4 MB, 40 MHz and recomputes its SHA-256, byte for byte what espflash writes at flash 0. Never commit ROM or bootloader files. Bump `rom::ROM_ELFS_RELEASE` or `bootloader::ESPFLASH_RELEASE` and both scripts together. Unmodelled registers the bootloader and esp-hal touch (RTC_CNTL power and clock trim, analog I2C, RF, the SAR ADC beyond its one-shot registers, APB_CTRL, SYSTEM, SENSITIVE, ASSIST_DEBUG) read as written; `tests/esp_hal_blinky.rs` fails if a new block shows up.
- **Pins to analog:** `Esp32c3Engine` turns changes on linked pins into kernel events (`pin_code`: pin, drive strength, low/high/Hi-Z) at the exact hart time and returns early there; register it before the analog engine and map every code from `all_pin_codes(pin)` to `PinDriver` `v`/`r` with `PinOut::thevenin` (output resistance about 120/60/30/15 Ω per drive strength: an estimate, not a datasheet value; the weak pulls `FUN_WPU`/`FUN_WPD` are 45 kΩ, the datasheet's typical value, in parallel; `pin_code` carries the pulls in bits 4 and 5, so there are 48 codes per pin).
- **Analog to pins (GPIO inputs):** `Esp32c3Engine::link_input(pin, level)` marks a pin external (`Gpio::set_external`: its pad level comes from outside, not its own output loop-back and pulls) and gives its level at the start (`initial_input_level` of the operating point: high at or above half VDD). Add the two `input_watches(pin, vdd)` to the analog engine (rising through V_IH = 0.75 VDD sends `input_code(pin, true)`, falling through V_IL = 0.25 VDD sends `input_code(pin, false)`, target the CPU engine): the datasheet's guaranteed limits act as a Schmitt trigger; real pads switch somewhere in between. `GPIO_IN` reads a pad only with `FUN_IE` set. Reads are exact in time: with inputs linked, `SocBus::defer_load` stops the hart before any load of `GPIO_IN`, `GPIO_STATUS`, `GPIO_PCPU_INT` or `GPIO_PCPU_NMI_INT` made after the slice start (the last time inputs are known); the engine returns there, the analog engine catches up and delivers its crossings, and the load runs next slice. When every engine reports quiescent at the slice start (`SyncCtx::peers_quiescent`), the input horizon is cleared so a tight poll loop can batch through the quantum without per-read slices. A hart in `wfi` only claims the slice (`local_time` is the claim) and an input event wakes it at the event's own time. A busy hart not reading inputs can be ahead of an input event by up to one slice, so a pin interrupt may be taken that late; `Esp32c3Engine::set_max_lead` bounds it at the cost of more slices. A tight polling loop costs one kernel slice per input read (`tests/esp_hal_button.rs`: about 14 000 slices per simulated millisecond, still fast).
- **ADC (`saradc`):** APB_SARADC one-shot mode (`ONETIME_SAMPLE`: unit select, channel, attenuation, START on a rising edge): ADC1 channels 0 to 4 are pads 0 to 4 (GPIO0 to GPIO4), ADC2 channel 0 is pad 5 (GPIO5). A conversion takes 25 SAR clocks (SAR_CLK = APB 80 MHz, or 240 MHz with `CLK_SEL` = 1, / (`DIV_NUM` + 1 + A/B) / `SAR_CLK_DIV`: 6.25 µs at reset values; the divider formula follows ESP-IDF's digital clock setup, an assumption), then sets `SARn_DATA_STATUS` and the `ADCn_DONE` interrupt (matrix source 43, `APB_ADC`). The voltage comes from the circuit: `Esp32c3Engine::link_adc(pad, target)` makes a conversion start send `adc_request_code(pad)` and return at that instant; the analog engine's `sample_on(code, "v(node)", 0, adc_value_code(pad))` answers at once with the node voltage (1 µV steps), which the conversion uses. Unlinked pads use `Esp32c3::set_adc_input` (default 0 V). The code is the inverse of Espressif's ESP32-C3 calibration (line through the eFuse calibration point, then the error-curve polynomial esp-hal and ESP-IDF use), so a calibrated reading recovers the input within 3 mV (`saradc::code_for`, `calibrated_mv`). ADC2 uses the ADC1 curve and works (the chip's ADC2 errata is not modelled). Not modelled: noise and INL/DNL beyond the curve, the sampling capacitor's load on the node, regi2c analog settings (init code, DREF; I2C_ANA_MST stays unmodelled), XPD/FSM wait times, continuous (pattern table, DMA) mode, filters, thresholds and the temperature sensor.
- **LEDC (`ledc`):** four timers (`CLK_SEL` in `LEDC_CONF`: 1 = APB 80 MHz, 2 = RC_FAST 17.5 MHz, 3 = XTAL 40 MHz; fractional divider A + B/256 with tick g ending after floor((phase + g·(256A + B))/256) clocks; `DUTY_RES` 1 to 14 bits; `PAUSE`, `RST`; `PARA_UP` applies at the next overflow, or at once in or on leaving reset) and six channels (Hpoint, Lpoint = Hpoint + `DUTY[18:4]`, plus one in `DUTY[3:0]` of every 16 periods for dither; a duty of 2^res or more stays high; channel `PARA_UP` latches Hpoint, `SIG_OUT_EN`, timer select and overflow counting at the next overflow, while fade settings and the new duty take effect at once, as TRM 32.3.4 says; fades step `DUTY_SCALE` every `DUTY_CYCLE` overflows `DUTY_NUM` times, then `DUTY_CHNG_END`; overflow counter interrupt after `OVF_NUM` + 1 overflows; `IDLE_LV` when off). Interrupts: matrix source 23. Outputs are GPIO matrix signals 45 to 50 (`OUT_SEL`); `Gpio::set_output_signal` drives routed pins with `INV_SEL` and the peripheral's or `GPIO_ENABLE`'s output enable (`OEN_SEL`, `OEN_INV_SEL`). PWM is not averaged: every output change is a `SignalChange` at its exact tick, applied in time order at the next sync (`Esp32c3::sync`), stamped as a pin edge at that time, and the engine returns there so the analog engine sees each edge. Overflows that change nothing are skipped in bulk, so a static duty costs nothing between edges, but every edge is a kernel event: cost grows with the PWM frequency (the 1 kHz and 5 kHz tests take seconds). `TIMERx_VALUE` reads the counter as of the last sync.
- **Test firmware:** `firmware/esp32c3-blinky` (`blinky.S`, polled SYSTIMER), `firmware/esp32c3-timer-irq` (`timer_irq.S`: disables the watchdogs, SYSTIMER period alarm and TIMG0 auto-reload alarm through the interrupt matrix into vectored handlers, `wfi` between them) and `firmware/esp32c3-xip-blinky` (`xip_blinky.S`: a direct-boot flash image, `xip_blinky.bin` at flash 0, running in place from IROM with its banner and a table in DROM; booted by the real ROM in `tests/rom_boot.rs` and by ROM-lite in `tests/flash_boot.rs`), each with `link.ld` and `build.sh`, and `firmware/esp32c3-esp-hal-blinky` (Rust, esp-hal 1.2.2, its own Cargo workspace and pinned Rust 1.95.0; `build.sh` cuts `partitions.bin` and `app.bin` from `espflash save-image --merge` with espflash 4.7.0 and pins `SOURCE_DATE_EPOCH`; booted through the ROM and the ESP-IDF bootloader in `tests/esp_hal_blinky.rs`) and `firmware/esp32c3-esp-hal-button` (the same setup with esp-hal's `unstable` feature: `button_poll.bin` polls a button on GPIO9 into the LED on GPIO8, `button_irq.bin` toggles the LED from a GPIO falling-edge interrupt and sleeps in `wfi`; `tests/esp_hal_button.rs` co-simulates them with the `generic.pushbutton` part, the internal pull-up, bounce and an RC edge) and `firmware/esp32c3-esp-hal-adc-pwm` (the same setup: `pot_dimmer.bin` reads a pot on GPIO2 through ADC1 with `AdcCalCurve` and sets a 1 kHz, 10-bit LEDC duty on GPIO8; `led_fade.bin` fades the LED up and down with the LEDC hardware fade at 5 kHz, 8-bit; `tests/esp_hal_adc_pwm.rs` co-simulates them with `bourns.ptv09a-b103` turned at run time and the LED circuit) (overview in `firmware/README.md`): bare-metal RV32IMC assembly built with zig (`pip install ziglang==0.17.1`). ## 4. Coding conventions

- Rust **edition 2024**, **MSRV 1.95** (egui 0.37 needs it). Toolchain pinned to stable via `rust-toolchain.toml`.
- Formatting: `cargo fmt --all` (config in `rustfmt.toml`, max width 120).
- Lints: `cargo clippy --workspace --all-targets -- -D warnings` must be clean. Workspace lints deny `unsafe_code` and warn on `missing_docs`; every public item gets a doc comment.
- Tests: every new behaviour gets unit tests in the same crate; numeric code compares with tolerances, never exact floats. Prefer small deterministic tests; analog results are validated against closed-form answers and ngspice (section 3b).
- Dependencies: add them once in the root `[workspace.dependencies]` and use `x.workspace = true` in crates. Keep heavy dependencies (egui, wgpu, wasmtime) behind the crates or features that need them. Only list an internal path in `[workspace.dependencies]` while some crate actually depends on it; stub crates stay workspace members, and re-add the path entry when the first consumer lands (see the crate map above).
- Errors: `thiserror` in libraries; no `unwrap()` in library code outside tests.
- Units: SI units in `f64` for analog values; simulation time is always `of_core::SimTime` (picoseconds), never wall-clock.
- Determinism: no `HashMap` iteration order, threads, or wall-clock time influencing simulation results.
